# VI. SỬA CÁC KHOẢNG TRỐNG DATABASE

Không sửa migration cũ.

Tạo migration mới để bổ sung các thiếu sót an toàn.

## 1. sessions.user_id

Kiểm tra dữ liệu và engine trước khi thêm FK:

```text
sessions.user_id
→ users.id
```

Quy tắc delete:

```text
nullOnDelete
```

Chỉ thêm nếu không phá dữ liệu hiện tại.

## 2. job_positions.company_id

Thêm FK:

```text
job_positions.company_id
→ companies.id
```

Phải kiểm tra dữ liệu orphan trước khi thêm.

## 3. Unique indexes

Bổ sung nếu chưa tồn tại:

```text
work_shifts(company_id, code)
leave_types(company_id, code)
learning_courses(company_id, code)
```

Không tạo index trùng.

## 4. User profile

Không nhồi toàn bộ hồ sơ nhân viên vào bảng `users`.

`users` chỉ là tài khoản xác thực.

Tạo migration mới bổ sung các trường quản trị hợp lý nếu chưa có:

```text
uuid
avatar_url nullable
thumbnail_url nullable
phone nullable
status enum(active, inactive, locked)
last_login_at nullable
last_login_ip nullable
locale default vi
timezone default Asia/Ho_Chi_Minh
```

Nếu hệ thống đã dùng Media/R2 thì ưu tiên:

```text
avatar_media_id nullable
```

Thay vì lưu file trực tiếp.

Không lưu ảnh base64 trong database.

Không bắt buộc User phải là Employee.

Một User có thể:

* Là tài khoản quản trị hệ thống.
* Liên kết với một Employee.
* Không có Employee.
* Bị khóa mà hồ sơ Employee vẫn còn.

Quan hệ:

```text
User hasOne Employee
Employee belongsTo User nullable
```

## 5. Company thiếu trường giao diện

Không thay đổi bảng nếu chưa thật sự cần.

Nếu logic Company cần thêm:

```text
short_name
email
phone
website
address
legal_representative
description
logo_url hoặc logo_media_id
deleted_at
created_by
updated_by
```

thì tạo migration bổ sung mới.

Phải cân nhắc dữ liệu hiện tại và nullable hợp lý.

## 6. Soft delete

Không tự động thêm `deleted_at` cho tất cả bảng.

Chỉ thêm cho các master data hoặc hồ sơ cần khôi phục, ví dụ:

```text
companies
organization_units
job_positions
employees
candidates
learning_courses
```

Không dùng soft delete tùy tiện cho:

```text
payroll_items
workflow_actions
integration_logs
attendance_records đã khóa
activity_log
```

Các bản ghi audit và tài chính phải ưu tiên bất biến hoặc khóa trạng thái.
